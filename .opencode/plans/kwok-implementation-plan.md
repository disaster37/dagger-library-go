# kwok Module — Implementation Plan

Status: implementation-ready
Target module: `/projects/dagger-library-go/kwok/`
Reference module: `/projects/dagger-library-go/k3s/` (structural template)

## 1. Goal

Finish the partially-implemented `kwok` Dagger module so it:

1. Mirrors the k3s module's structure, method signatures, and conventions.
2. Ships kwok `Stage` configs that simulate the pod lifecycle (Pending → ContainerCreating → Running/Ready, plus init containers, completion, and deletion), which makes Deployment rolling updates observable.
3. Supports operator testing: apply manifests, wait for deployments, simulate a rolling update, and hand a kubeconfig/service to an operator under test.

KWOK (Kubernetes WithOut Kubelet) runs a real kube-apiserver/etcd/controller-manager/scheduler but simulates kubelets. Pods never run real containers; the kwok-controller drives pod status transitions from `Stage` rules. This gives operators a full API surface to reconcile against, with near-zero footprint.

## 2. Verified context (do not re-derive)

### 2.1 Repo facts

- k3s pattern (`k3s/main.go`): `New()` only prepares a container (image + cgroup-fix entrypoint script + cache mounts + `WithExposedPort(6443)`); the cluster starts lazily in `Server()` via `AsService(ContainerAsServiceOpts{UseEntrypoint: true, Args: ["sh","-c", cmd], InsecureRootCapabilities: true})`; kubeconfig persists in a cache volume; `Config(ctx, local)` copies it out and rewrites to `localhost` only when `local=true`; `Kubectl`/`Kns` use `bitnami/kubectl` / `derailed/k9s` with `WithFile("/.kube/config", m.Config(ctx,false), ContainerWithFileOpts{Owner: "1001"})` + `WithUser("1001")`.
- Every module that imports `lib` (helm, golang, image, operator-sdk, git-module) has BOTH:
  - `go.mod`: `replace github.com/disaster37/dagger-library-go/lib => ../lib/`
  - `dagger.json`: `"include": ["../lib"]`
  kwok has **neither** today (it pins a published pseudo-version). Both must be added.
- `lib/helper` provides `ForgeCommand`, `ForgeCommandf`, `ForgeScript` (`lib/helper/command.go`).
- VERSION/version.go convention (`helm/version.go`, identical in golang/image/operator-sdk):
  ```go
  package main

  import _ "embed"

  //go:embed VERSION
  var ModuleVersion string
  ```
- `scripts/release.sh` bumps VERSION only for `helm golang image operator-sdk`.
- Prior decision (`.opencode/plans/ci-pipeline-generator.md`): k3s and kwok are runtime-only cluster helpers and intentionally get **no `GenerateCi`**.
- Dagger SDK is v0.16.1 (`engineVersion` in `dagger.json`); generated code import path is `dagger/kwok/internal/dagger`. `dagger.gen.go` + `internal/` are gitignored and regenerated by `dagger develop`.
- operator-sdk consumes k3s via `dag.K3S(...)` and starts the cluster eagerly with `.Server(...).Start(ctx)` before kubectl work (`operator-sdk/kube.go`) — the same eager-start pattern is used here for the new imperative methods.

### 2.2 Upstream kwok facts (verified against kubernetes-sigs/kwok source)

- The all-in-one image `registry.k8s.io/kwok/cluster:<kwok-ver>-k8s.<k8s-ver>` (e.g. `v0.6.1-k8s.v1.31.1`) contains `kwok` and `kwokctl` in `/usr/local/bin`, and its build pre-downloads ALL component binaries (etcd, kube-apiserver, kube-controller-manager, kube-scheduler, kubectl) into `/root/.kwok/cache`. Therefore `kwokctl create cluster --runtime binary` inside this image needs **no downloads** as long as nothing shadows `/root/.kwok/cache`.
- Image default env (must be overridden): `KWOK_KUBE_APISERVER_PORT=0` (random secure port), `KWOK_KUBE_APISERVER_INSECURE_PORT=8080`, `KWOK_RUNTIME=binary`. Pass explicit flags: `--kube-apiserver-port 6443 --kube-apiserver-insecure-port 0` → secure-only API on 6443, and `kubeconfig.yaml` becomes `https://127.0.0.1:6443` with embedded CA + admin client cert.
- Cluster workdir: `/root/.kwok/clusters/<name>/`; host kubeconfig file name is `kubeconfig.yaml` (const `InHostKubeconfigName` in `pkg/kwokctl/runtime/cluster.go`). Logs live in `<workdir>/logs/`.
- TLS SANs: at cluster creation kwokctl generates PKI including **all host IPs** (`utilsnet.GetAllIPs()` in `cluster_setup.go`) plus `localhost`/`127.0.0.1`. So rewriting the kubeconfig server to the container IP passes TLS verification.
- `kwokctl create cluster -c <file>` accepts Stage objects (`kwok.x-k8s.io/v1alpha1`) and stores them in the cluster config; when stages are supplied, default pod stages are not injected (default node stages still are, so nodes become Ready).
- `--name` is a persistent root flag on kwokctl → valid on `create`, `start`, `scale`, `logs`, `kubectl`.
- `kwokctl scale` usage: `kwokctl scale [kind] [name] --replicas N --name <cluster>` (e.g. `kwokctl scale node node --replicas 3 --name test`).
- The image's own entrypoint (`kwokctl create cluster "$@"` + keep-alive loop) is replaced by our own entrypoint, mirroring k3s.

### 2.3 Bugs in the current kwok code that this plan fixes

1. **Fatal design bug**: cluster is created inside `New()` via `WithExec`. kwokctl binary-runtime starts etcd/apiserver/etc. as processes of that build step; they die when the step ends. `Server()` only tails controller logs, so it serves a dead cluster. Fix: create/start the cluster inside the `Server()` service command (k3s pattern).
2. `Config()` calls `panic(err)` on the `ip route` exec — panics are banned; the IP rewrite moves into the service startup script.
3. `Config()` local rewrite is inverted (rewrites only when `local=false`) and uses a fragile exec; k3s rewrites to `localhost` only when `local=true`.
4. `kwokctl scale node node --replicas N` is missing `--name <cluster>` → targets the wrong (default) cluster.
5. `ContainerWithFileOpts{Permissions: 1001}` confuses file-mode with owner; k3s uses `Owner: "1001"`.
6. Mounting a fresh cache volume over `/root/.kwok/cache` shadows the image's baked-in binaries and forces ~100MB of downloads; the bin/kube caches (`kwok_bin`, `kwok_kube`) are removed.
7. Manual kwokctl download via `alpine/curl` + `kwokVersion` param is replaced by the official cluster image.
8. Stale doc comments referencing "k3s cluster"; stray `Terminal()` calls not present in k3s.

## 3. Architecture decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Base image = `registry.k8s.io/kwok/cluster:v0.6.1-k8s.v1.31.1` (overridable via `image` param). Used as a "kwokctl preinstalled" base; the image's own entrypoint is overridden. | Removes curl/binary-download fragility; offline cluster creation. |
| D2 | Cluster is created/started lazily in `Server()` via `AsService(UseEntrypoint: true, Args: ["sh","-c", startupScript])`. `New()` only prepares the container definition. | Matches k3s; fixes the dead-cluster bug; service start = cluster start. |
| D3 | Startup script: `create` with fallback to `start` (idempotent restart from persisted cache), readyz check, optional node scaling, kubeconfig rewrite to container IP, then `exec kwokctl logs kwok-controller -f --name <name>` as keep-alive. | Cache volume persists cluster state across service starts; tailing logs keeps the service process alive and surfaces controller logs via `dagger logs`. |
| D4 | Secure-only API: `--kube-apiserver-port 6443 --kube-apiserver-insecure-port 0`. | Matches k3s (https/6443) and existing sed patterns; admin-credential kubeconfig is more realistic for operator tests. |
| D5 | Keep the existing 7 Stage manifests (pod-create, pod-init-container-running, pod-init-container-completed, pod-ready, pod-complete, pod-remove-finalizer, pod-delete) byte-for-byte as a Go const; they are written to `/kwok/config.yaml` and passed via `-c`. | They already implement Pending → ContainerCreating → Running/Ready plus deletion via finalizers; ~1–6s delay per transition keeps intermediate states observable for operators. |
| D6 | Only one cache volume: `kwok_cluster_<name>` → `/root/.kwok/clusters/<name>` (struct field stays `ClusterCache`). No mount over `/root/.kwok/cache`. | Preserves baked-in binaries; cluster state (etcd, pki, kubeconfig) persists. |
| D7 | k3s-style split of API styles: `Server`/`Config`/`Kubectl`/`Kns`/`WithContainer`/`WithExec` are lazy builders (no error return, k3s-compatible signatures); `Apply`/`WaitForDeploymentReady`/`SimulateRollingUpdate` are imperative (take ctx, return errors, eagerly start the service via `m.Server().Start(ctx)` and wait for the apiserver). | Mirrors k3s for shared surface; imperative methods need real error handling and cluster-readiness gating (requirements D11–D15). |
| D8 | `Server()` accepts `clusterCidr`/`serviceCidr` optional params for k3s signature parity; when non-empty they are wired via kwokctl `--extra-args`: `kube-controller-manager=--cluster-cidr=<v> --allocate-node-cidrs=true` and `kube-apiserver`/`kube-controller-manager` `--service-cluster-ip-range=<v>`. | Required by spec; CIDRs rarely matter for kwok, so this is flagged for manual verification (see §10). |
| D9 | `GenerateCi` is out of scope (repo decision for runtime-only modules). VERSION/version.go are still added for convention and future use. | `.opencode/plans/ci-pipeline-generator.md`. |
| D10 | `kwokVersion` constructor param is removed (version is now tied to the image tag); `New()` loses its `ctx` (no eager work). Breaking changes are acceptable: module is unfinished and unreferenced elsewhere in the repo. | Verified: no other module imports kwok. |

## 4. Exact code design

All code lives in `/projects/dagger-library-go/kwok/main.go` (plus `version.go`). Import path: `dagger/kwok/internal/dagger`.

### 4.1 Struct

```go
type Kwok struct {
	// +private
	Name string

	// +private
	ClusterCache *dagger.CacheVolume

	// +private
	Nodes int

	Container *dagger.Container
}
```

(`Nodes` is stored because node scaling now happens in `Server()`'s startup script, not in `New()`.)

### 4.2 Constants

- `entrypoint` — copy **verbatim** from `k3s/main.go` lines 17–40 (cgroupV2 fix + `exec "$@"`), including the moby/dind disclaimer block.
- `podLifecycleStages` — the exact Stage YAML currently in `kwok/main.go` lines 78–444 (7 Stage documents), unchanged.
- `defaultImage = "registry.k8s.io/kwok/cluster:v0.6.1-k8s.v1.31.1"`.
- `kubeconfigPathFmt = "/root/.kwok/clusters/%s/kubeconfig.yaml"`.
- Polling constants: `pollInterval = 2 * time.Second`, `apiserverReadyTimeout = 120` (seconds), default deployment timeout `300`.

### 4.3 Constructor

```go
func New(
	// The cluster name
	name string,

	// The number of nodes (1 default node when <= 1)
	// +optional
	nodes int,

	// The kwok cluster image to use
	// +optional
	// +default="registry.k8s.io/kwok/cluster:v0.6.1-k8s.v1.31.1"
	image string,
) *Kwok
```

Body (lazy only, no ctx, no error):

1. `clusterCache := dag.CacheVolume("kwok_cluster_" + name)`
2. `ctr := dag.Container().From(image)`
   - `.WithNewFile("/usr/bin/entrypoint.sh", entrypoint, dagger.ContainerWithNewFileOpts{Permissions: 0o755})`
   - `.WithEntrypoint([]string{"entrypoint.sh"})`
   - `.WithMountedCache("/root/.kwok/clusters/"+name, clusterCache)`
   - `.WithNewFile("/kwok/config.yaml", podLifecycleStages)`
   - `.WithExposedPort(6443)`
3. Return `&Kwok{Name: name, ClusterCache: clusterCache, Nodes: nodes, Container: ctr}`.

No `binCache`/`kubeCache`, no curl download, no `Terminal()`.

### 4.4 Server

```go
// Returns the kwok cluster as a service
func (m *Kwok) Server(
	// Alternative cluster CIDR (k3s parity; wired via kube-controller-manager extra args)
	// +optional
	clusterCidr string,

	// Alternative service CIDR (k3s parity; wired via apiserver/controller-manager extra args)
	// +optional
	serviceCird string,
) *dagger.Service
```

Build `script := m.forgeServerScript(clusterCidr, serviceCird)` (pure helper, §4.10) and return:

```go
return m.Container.AsService(dagger.ContainerAsServiceOpts{
	UseEntrypoint:          true,
	Args:                   []string{"sh", "-c", script},
	InsecureRootCapabilities: true,
})
```

`forgeServerScript` output (fmt-built; `%s` = cluster name; CIDR extra-args and scale line conditional):

```sh
set -o errexit
set -o nounset

if ! command -v kwokctl >/dev/null 2>&1; then
  echo "ERROR: kwokctl not found in the container image. Use a kwok cluster image such as registry.k8s.io/kwok/cluster:v0.6.1-k8s.v1.31.1" >&2
  exit 1
fi

# Create the cluster on first start; restart it from persisted state afterwards.
if ! kwokctl create cluster --runtime binary --name <name> \
      --kube-apiserver-port 6443 --kube-apiserver-insecure-port 0 \
      -c /kwok/config.yaml <cidr-extra-args>; then
  echo "kwokctl create failed; trying to start existing cluster" >&2
  kwokctl start cluster --name <name>
fi

# Fail fast if the API server never answers.
kwokctl kubectl --name <name> get --raw=/readyz >/dev/null

<scale line, only when Nodes > 1: kwokctl scale node node --name <name> --replicas N>

# Publish the engine-network IP in the kubeconfig so other containers can reach the cluster.
IP=$(ip route | grep src | awk '{print $NF}')
if [ -z "$IP" ]; then
  echo "ERROR: unable to determine container IP for kubeconfig rewrite" >&2
  exit 1
fi
sed -i "s#https://[0-9.]*:6443#https://${IP}:6443#" /root/.kwok/clusters/<name>/kubeconfig.yaml

# Keep the service alive and surface controller logs.
exec kwokctl logs kwok-controller -f --name <name>
```

CIDR wiring (only when the corresponding param is non-empty):
- clusterCidr → `--extra-args kube-controller-manager=--cluster-cidr=<v> --extra-args kube-controller-manager=--allocate-node-cidrs=true`
- serviceCird → `--extra-args kube-apiserver=--service-cluster-ip-range=<v> --extra-args kube-controller-manager=--service-cluster-ip-range=<v>`

### 4.6 Config

```go
// Returns the kubeconfig for the kwok cluster
func (m *Kwok) Config(ctx context.Context,
	// Rewrite the server URL to localhost (use with a published port, e.g. `dagger call server up`)
	// +optional
	// +default=false
	local bool,
) *dagger.File
```

Body (k3s-shaped; NO exec against `m.Container`, NO panic):

```go
return dag.Container().
	From("alpine").
	// bust cache so we always fetch the freshest kubeconfig
	WithEnvVariable("CACHE", time.Now().String()).
	WithMountedCache("/cache/kwok", m.ClusterCache).
	WithExec([]string{"sh", "-c",
		"test -f /cache/kwok/kubeconfig.yaml || { echo 'ERROR: kubeconfig not found - start the cluster first with `server`' >&2; exit 1; } && cp /cache/kwok/kubeconfig.yaml kubeconfig.yaml"}).
	With(func(c *dagger.Container) *dagger.Container {
		if local {
			c = c.WithExec([]string{"sed", "-i", `s#https://[0-9.]*:6443#https://localhost:6443#`, "kubeconfig.yaml"})
		}
		return c
	}).
	File("kubeconfig.yaml")
```

Non-local configs already contain the container IP (rewritten by the startup script), exactly like k3s.

### 4.7 Kubectl / Kns

Mirror k3s exactly (fixing the Permissions→Owner bug and comments):

```go
// Runs kubectl on the target kwok cluster
func (m *Kwok) Kubectl(ctx context.Context, args string) *dagger.Container
// runs k9s on the target kwok cluster
func (m *Kwok) Kns(ctx context.Context) *dagger.Container
```

Shared private base (avoids duplication and is reused by `Apply`/polling):

```go
func (m *Kwok) kubectlBase(ctx context.Context) *dagger.Container {
	return dag.Container().
		From("bitnami/kubectl").
		WithoutEntrypoint().
		WithMountedCache("/cache/kwok", m.ClusterCache).
		WithEnvVariable("CACHE", time.Now().String()).
		WithFile("/.kube/config", m.Config(ctx, false), dagger.ContainerWithFileOpts{Owner: "1001"}).
		WithUser("1001")
}
```

- `Kubectl` = `m.kubectlBase(ctx).WithExec([]string{"sh", "-c", "kubectl " + args})`
- `Kns` = k9s variant per k3s: `From("derailed/k9s")`, `WithoutEntrypoint()`, cache mount, CACHE env, `KUBECONFIG=/.kube/config`, `WithFile(..., Owner: "1001")`, `WithUser("1001")`, `WithDefaultTerminalCmd([]string{"k9s"})`. No `Terminal()`.

Note: mounting `ClusterCache` into these containers leaks no more than the kubeconfig already does (it embeds the CA + admin client cert), and keeps parity with k3s per instruction B6.

### 4.8 Apply

```go
// Apply a Kubernetes manifest to the cluster (provide exactly one of manifest or file)
func (m *Kwok) Apply(ctx context.Context,
	// Inline manifest YAML
	// +optional
	manifest string,

	// Manifest file
	// +optional
	file *dagger.File,
) (*dagger.Container, error)
```

Behavior:
1. Validate exactly one of `manifest`/`file` is provided → otherwise `error` ("provide exactly one of manifest or file").
2. `if err := m.startServer(ctx); err != nil { return nil, err }` then `m.waitForApiserver(ctx, apiserverReadyTimeout)`.
3. Build container: `m.kubectlBase(ctx)`; if string → `.WithNewFile("/tmp/manifest.yaml", manifest)`; if file → `.WithFile("/tmp/manifest.yaml", file)` (default opts; file readable by user 1001 — set `Owner: "1001"`).
4. Return `ctr.WithExec([]string{"sh", "-c", "kubectl apply -f /tmp/manifest.yaml"})`.

### 4.9 WaitForDeploymentReady

```go
// Polls until the deployment reports all replicas ready
func (m *Kwok) WaitForDeploymentReady(ctx context.Context,
	// Deployment name
	name string,

	// Timeout in seconds
	// +optional
	// +default=300
	timeout int,

	// Namespace
	// +optional
	// +default="default"
	namespace string,
) error
```

Behavior:
1. Validate `name != ""`, `timeout > 0`.
2. `m.startServer(ctx)`.
3. Poll loop until `time.Now()` past deadline, sleeping `pollInterval` between attempts (with `ctx.Done()` select):
   - Run `m.kubectlBase(ctx).WithExec([]string{"sh","-c", fmt.Sprintf("kubectl get deployment %s -n %s --request-timeout=10s -o jsonpath='{.spec.replicas}|{.status.readyReplicas}|{.status.updatedReplicas}|{.status.observedGeneration}|{.metadata.generation}'", name, namespace)}).Stdout(ctx)`.
   - Feed stdout to pure helper `isDeploymentReady(stdout)` (§4.10). Ready → return nil.
   - Any exec/parse error → record as lastErr, keep polling.
4. On deadline: `return fmt.Errorf("deployment %q in namespace %q not ready after %ds: %w", name, namespace, timeout, lastErr)`.

### 4.10 SimulateRollingUpdate + pure helpers

```go
// Creates a Deployment, waits for it, updates its image and waits for the
// simulated rolling update to complete
func (m *Kwok) SimulateRollingUpdate(ctx context.Context,
	// Deployment name
	name string,

	// Initial container image
	image string,

	// Number of replicas
	replicas int,

	// Image to roll out
	newImage string,

	// Timeout in seconds for each readiness wait
	// +optional
	// +default=300
	timeout int,

	// Namespace
	// +optional
	// +default="default"
	namespace string,
) (*dagger.Container, error)
```

Behavior:
1. Validate: `name`, `image`, `newImage` non-empty; `replicas > 0`; `timeout > 0` → wrapped errors otherwise.
2. `m.startServer(ctx)` + `m.waitForApiserver(ctx, apiserverReadyTimeout)`.
3. Initial rollout: `manifest := forgeDeploymentManifest(name, image, replicas, namespace)`; apply eagerly: `m.kubectlBase(ctx).WithNewFile("/tmp/manifest.yaml", manifest).WithExec(... "kubectl apply -f /tmp/manifest.yaml").Sync(ctx)`; wrap errors.
4. `m.WaitForDeploymentReady(ctx, name, timeout, namespace)`.
5. Trigger rolling update: `m.kubectlBase(ctx).WithExec(["sh","-c", fmt.Sprintf("kubectl set image deployment/%s %s=%s -n %s", name, name, newImage, namespace)]).Sync(ctx)` (container name == deployment name by construction).
6. `m.WaitForDeploymentReady(ctx, name, timeout, namespace)` again — the Stage delays make new pods transition Pending → ContainerCreating → Running/Ready while the deployment controller scales the old ReplicaSet down, i.e. a full simulated rolling update.
7. Return `m.kubectlBase(ctx).WithExec(["sh","-c", fmt.Sprintf("kubectl rollout status deployment/%s -n %s", name, namespace)])` (lazy, for the caller to evaluate/export).

Pure, unit-tested helpers (same file):

```go
// forgeDeploymentManifest renders a Deployment with rolling-update strategy.
// Container name equals the deployment name so `kubectl set image` works.
func forgeDeploymentManifest(name, image string, replicas int, namespace string) string

// forgeServerScript builds the Server() startup script.
func (m *Kwok) forgeServerScript(clusterCidr, serviceCidr string) string

// isDeploymentReady parses the jsonpath output
// "<spec>|<ready>|<updated>|<observedGeneration>|<generation>".
// Empty numeric fields count as 0. Ready when spec>0 and
// ready==spec && updated==spec && observedGeneration==generation.
func isDeploymentReady(statusLine string) (bool, error)

// startServer starts the cluster service (idempotent).
func (m *Kwok) startServer(ctx context.Context) error {
	if _, err := m.Server().Start(ctx); err != nil {
		return fmt.Errorf("failed to start kwok cluster %q: %w", m.Name, err)
	}
	return nil
}

// waitForApiserver polls `kubectl get nodes` until it succeeds or the
// deadline passes; tolerates the kubeconfig not existing yet (retries).
func (m *Kwok) waitForApiserver(ctx context.Context, timeoutSecs int) error
```

`forgeDeploymentManifest` output shape:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: <name>
  namespace: <namespace>
  labels:
    app: <name>
spec:
  replicas: <replicas>
  selector:
    matchLabels:
      app: <name>
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1
      maxSurge: 1
  template:

      labels:
        app: <name>

      containers:
        - name: <name>

```

## 5. Error handling matrix (requirements D11–D15)

| Case | Handling |
|------|----------|
| Any failure | No `panic` anywhere; imperative methods return `fmt.Errorf` with `%w` context. The single panic in current `Config()` is removed by design (§4.6). |
| Cluster not running when imperative method is called | `startServer` + `waitForApiserver` gate inside `Apply`/`WaitForDeploymentReady`/`SimulateRollingUpdate`; clear error text mentions starting `server`. |
| Lazy methods (`Kubectl`, `Config`, …) called before cluster start | Fail at evaluation with the explicit shell check message from §4.6 (`start the cluster first with 'server'`). |
| Missing/invalid kubeconfig | `test -f` guard in `Config()`; polling treats missing kubeconfig as transient (retries until timeout). |
| kwokctl binary not found (custom `image` without kwok) | Startup script `command -v kwokctl` guard with actionable message (§4.4). |
| Network/API timeouts while waiting | `--request-timeout=10s` on poll kubectl commands; overall deadline + `ctx.Done()` in every loop; timeout errors include last observed status/error. |
| Stale/corrupt cluster state in cache | Documented: use a new cluster `name` (cache volumes are per-name). |

## 11. Risks & mitigations

| # | Risk | Mitigation |
|---|------|------------|
| R1 | kwok image tag `v0.6.1-k8s.v1.31.1` unavailable in the build environment | Tag is an official release; `image` param allows override. |
| R2 | `kwokctl logs -f` unsupported/behaves differently in v0.6.1 | Fallback keep-alive: `exec tail -f /root/.kwok/clusters/<name>/logs/kwok-controller.log` (verify during task 7). |
| R3 | CIDR `--extra-args` wiring (D8) incompatible with kwokctl v0.6.1 | Params are optional; if verification step 10 fails, keep the params for k3s parity but only emit a warning that kwok ignores them, and record that in README. |
| R4 | kwokctl attempts network access despite baked-in cache (version check) | Observe logs in validation step 4; worst case re-add a cache mount on `/root/.kwok/cache` seeded by a one-time download exec. |
| R5 | Service IP from `ip route` differs from the address other containers use | Pattern is proven by the k3s module in this repo; validation step 7 catches regressions. |
| R6 | Persisted cluster state created by an older kwok version breaks `start` | Documented: use a fresh cluster name; kwokctl itself warns on version mismatch. |

## 12. Out of scope (explicit)
